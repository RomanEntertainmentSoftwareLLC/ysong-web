# Ads Creative Studio project and edit contract

`ReusableAdCreative.studioProject` is the optional, versioned edit source for Ads creatives. The reusable creative keeps its existing music, media, CTA, caption, provenance, and render ownership. Campaign `AdCreative` rows and destination variants remain bindings and derived outputs. A project never copies object keys, signed URLs, or campaign credentials into clips.

## Timeline

- `schemaVersion: 1` is required. Readers reject unknown versions; migrations must be explicit.
- `durationFrames` and clip positions are integer frames. The rational `framesPerSecond` timebase gives exact timeline positions, including rates such as `30000/1001`. Clip intervals are half open: `[startFrame, startFrame + durationFrames)`. Keyframe frames are relative to their clip.
- `tracks` are ordered arrays. Visual and text tracks stack bottom to top; audio tracks are mixed in order. Clips are ordered by start frame within each track. Overlap is allowed for compositing and audio mixing. Optional `visible` on visual/text tracks, `muted` on audio tracks, and `locked` on all tracks default to false except visibility, which defaults to true. Locked tracks cannot be reordered or toggled in the editor.
- Visual clips resolve exactly one of `mediaId` through the owner's `backgroundMedia` or `overlayId` through its image/sticker/logo `overlays`; audio clips resolve `snippetId` through `audioSnippets`. Source in/out seconds are relative to the referenced asset. The renderer must verify these ranges against authoritative asset durations and rights before rendering. Text clips own text and style and may retain an `overlayId` or `source` (`caption`/`cta`) for source identity. Clips never copy object keys or signed URLs.
- Audio mix controls remain non-destructive instructions on the reusable creative: clip `volume` (0–1), optional clip `muted`, `audioFadeInSeconds`, `audioFadeOutSeconds`, and `duckingIntent` (`none` or `under-voiceover`). Audio tracks may be muted and may set `waveformVisible` (editor display only). Preview and render use the same clip gain, mute, and linear fade envelope; ducking is an editorial intent until a voiceover track and renderer-side ducking policy are available. These fields never modify the promoted source audio.
- Transforms use normalized canvas coordinates, scale (1 is native), degrees, and opacity from 0 to 1. Audio volume is 0 to 1. Editable keyframes cover position x/y (−1–2, allowing off-canvas motion), scale (0–3), rotation (−180–180 degrees), opacity (0–1), and volume (0–1). Each clip allows at most 200 keys and one key per property/frame. Frames are clip relative. Before the first key, the base property value linearly approaches that key; between keys, the earlier key's `hold` or `linear` mode controls interpolation; after the last key, its value holds. `cut` has zero duration; fades and dissolves consume clip frames. Editors must preserve unknown future fields only by declining to edit an unknown schema version.
- The project render block specifies canvas, H.264/AAC, and background. Rendered object keys and statuses stay on the reusable creative's existing `renders` fields; they are invalidated when the project changes.

## Persistence

The frontend validates loaded and outgoing JSON with `validateCreativeStudioProject`. `GET /api/tools/promotion/creatives/:creativeId/studio-project` returns `{ project: CreativeStudioProject | null }`. Saving targets `PUT` at the same path with `{ expectedRevision, project }`; `expectedRevision` and `project.edit.parentRevision` equal the revision the editor loaded. These APIs are a contract for the promotion backend, which is outside this repository and is **not implemented here**.

The backend must authenticate and authorize the reusable creative owner, validate the referenced snippet/media IDs against that creative, verify source ranges, enforce payload limits, and atomically compare the persisted revision before replacing the project. On success it increments `revision`, updates `edit.updatedAt`, stores the edit transactionally, marks derived renders stale, and returns the updated reusable creative. On mismatch it returns HTTP 409 with the current revision; clients must reload or explicitly merge, never retry a blind overwrite. Failed validation must leave the prior edit and render references untouched. A missing project starts at revision 0. Deleting source media referenced by a saved project requires an explicit edit or rejection.

## Reel export

The existing 9:16 reel export button loads the saved project from the reusable creative. When present, the browser reel exporter resolves source IDs through that creative, records the selected 9:16 variant, and includes the Studio revision in the downloaded manifest. The legacy source-render export remains for creatives without a saved project. Studio export requires browser H.264/AAC MP4 recording support and accessible signed media URLs. It rejects missing sources, invalid trims, and voiceover ducking or nonvisual transitions that the browser renderer cannot perform. Unsaved timeline changes are not exported. Server-side derived render and Meta publishing integration remain backend responsibilities.

## Selected range AI video

The client reads an optional `AdCreative.metadata.aiVideoCapabilities` object with a nonempty `provider`, explicit `regenerate`, `extend`, and `fill` booleans, and a finite `maxDurationSeconds` up to 60. Missing or malformed capabilities enable nothing. Extension additionally requires the selected clip to be generated by that same provider and an open interval immediately after it. A fill request targets an actual gap on the selected visual track. Each request is bounded by exact integer start and duration frames on the active aspect variant and by the provider's duration limit.

Range requests currently remain local drafts. There is no provider submission endpoint in this repository. A future backend must authorize the creative and source, validate the selected range and provider capability again, and return completed jobs in `metadata.aiVideoJobs` with `artifact.metadata.requestId` linking to the draft request ID. The client only offers acceptance for a completed authorized job owned by the creative, from the matching provider and request, whose artifact covers the full requested range. It rechecks the range, clip version, capability, and duration at acceptance. Regeneration replaces the selected clip only after acceptance; fill and extension add a clip within the gap. Studio Undo can restore the prior local version until save.
