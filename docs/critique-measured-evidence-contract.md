# Critique measured-evidence contract

`buildCritiqueEvidence` is the version 1 boundary between the local technical analyzer and the artist-facing AI Critic. The client sends `{ evidence: CritiqueEvidencePacket }` to `/api/critique/ai-summary`; it never sends the full report. The receiving service must validate the same schema at its trust boundary before adding the packet to model context. It must request a version 1 `AiCritiqueSummary` and instruct the model to cite evidence IDs, describe candidates as checks to audition, and avoid inventing defects, measurements, severity, or certainty.

The packet identifies the asset, engine, analysis mode, and duration. Finding evidence carries the analyzer's code, severity, confidence, optional time and frequency ranges, and source. Its `derived` class means an analyzer inference rather than a direct measurement. Numeric metric evidence carries a named value and unit; estimated tempo and dynamic-range proxy are explicitly `derived`. Analyzer titles, descriptions, recommendations, verdict, score, and arbitrary metric maps are excluded from model context. Missing metrics do not become inferred values.

AI output is commentary only. Each interpretation cites one or more IDs from the current packet and has separate low/medium/high interpretation confidence plus a suggested listening check. It cannot add severity, metric values, time ranges, actions, or defect fields. The client rejects extra fields, unknown IDs, malformed text, and common unsupported certainty claims before display. The heading is fixed by the client; analyzer limitations are shown separately from the report. The original measured findings remain visible beside AI notes, so the artist can inspect and audition them.

Response validation cannot prove that free prose is factually grounded. The service must use the same packet, validate citations, and keep the model instruction narrow; a model failure should produce an unavailable AI note rather than alter the technical results. When the endpoint has not adopted version 1, the client displays its existing AI error state instead of showing an unvalidated legacy summary.
