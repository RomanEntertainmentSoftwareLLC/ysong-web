# Ads Smart Assistant context contract

`buildAdsAssistantContext` in `src/tools/promotion/adsSmartAssistantContract.ts` is the version 1 model input boundary. It uses the selected `AdCampaign`, its linked Smart Link, the selected release and verified track, campaign snippets and selected creatives, optional in-session Audio Intelligence analysis and edit cuts, saved Creative Studio projects, and optional paid analytics. Callers must load the saved Studio project for a selected reusable creative before including its timeline. Missing data is represented by `null`, empty arrays, and `unavailable`; it must not be fabricated.

The builder rejects mismatched campaign, Smart Link, release, track, genre analysis, selected creative, and analytics IDs. Callers must pair genre analysis with the track ID it analyzed. A track is considered verified only when it comes from the selected release, matches `sourceTrackId`, and has a source audio object key. The key itself is never copied into context. Snippets are scoped to the selected campaign and source track. Studio projects use the existing project validator and pass only timeline positions, source IDs, text, and revision. The context omits audio and media object keys, signed URLs, credentials, account IDs, raw targeting metadata, visitor data, and raw analytics rows.

`evidence` contains observed product state and measured analysis or analytics. `genre.analysis` records the Audio Intelligence engine, confidence, and ranked labels; its labels and tempo are estimates, not certified facts. `hooks` are artist-selected snippets with optional beat cut suggestions. Their times are edit ideas, not measured engagement. `analytics` is explicitly timestamped and marked stale when the API says so. The assistant must not promote missing data into measured claims.

Model output must conform to `AdsAssistantResponse` and pass `validateAdsAssistantResponse` before display or storage. It has only a plain summary and up to eight advisory suggestions with rationale, confidence, and paths to scalar context evidence. A suggestion may have no evidence paths, but must then be treated as an inference. Output has no command, API request, tool call, executable code, patch, or campaign mutation field. Unknown fields and paths to unavailable evidence are rejected. Render text as text; never interpret model content as HTML, code, publishing instructions, or authorization. Budget, targeting, creative, and publishing changes remain in the existing artist-controlled Promotion Center flows.

This contract does not add a model endpoint or automatic campaign action. A backend integration must enforce the same version, field limits, identity checks, and response allowlist at its trust boundary.
