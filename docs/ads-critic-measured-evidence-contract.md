# Ads Critic measured-evidence contract

`buildAdsCriticFixSuggestions` maps supported deterministic findings from the saved packet into Creative Studio edit proposals. It requires the exact Studio revision and timebase, resolves clip IDs in the packet's aspect, and runs each edit through `previewStudioEditProposal` before showing it. Opening delay, late CTA, dense text, and long visual holds with beat markers can produce editable suggestions. Visual gaps and long holds without beat markers remain review steps for the existing video tools; they never create media or alter tracks automatically. The artist previews the before/after, explicitly applies the edit to local Studio history, and separately saves the timeline. Undo/redo remain available before save; editing or switching aspects invalidates the pending preview.

`buildAdsCriticEvidence` in `src/tools/promotion/adsCriticEvidenceContract.ts` is the version 1 boundary between a deterministic Ads Critic and artist-facing critique. It accepts only a validated, saved Creative Studio project, its source ID lists, one selected aspect variant, a capture time, and bounded deterministic signals. The packet records the reusable creative ID, exact Studio revision, rational frame timebase, and half-open frame ranges. Rebuild it when the project revision changes; never carry findings forward onto an edited timeline.

## Evidence classes

- **Measured:** A direct numeric observation from Studio metadata or a deterministic analyzer. Confidence is 1 for the recorded value, not for an effect on viewers. The code allowlist is `timeline_duration`, `visual_gap`, `audio_gap`, and `overlay_duration`. A metadata observation proves only what is encoded in the saved project; a visual gap in metadata does not prove that the exported frame is black.
- **Heuristic:** A rule-based concern using an observed value and a named, versioned threshold in the same unit. The allowlist is `brief_opening`, `dense_text`, `late_cta`, and `long_visual_hold`. Confidence is below 1, severity cannot be critical, and copy should invite an artist to preview or test the choice. Thresholds are editorial rules, not measured engagement or platform requirements.
- **Uncertainty:** A known limit with no numeric observation or threshold. The allowlist is `render_unchecked`, `source_duration_unverified`, and `placement_unverified`. It cannot be critical or described as an observed defect. Missing input produces an uncertainty or no finding, never a fabricated measurement.
- **AI interpretation:** Optional text in `AdsCriticResponse`, separate from the immutable packet. Each interpretation cites one or more current evidence IDs, has its own low/medium/high confidence, and suggests a check the artist can perform. AI cannot add signal codes, metric values, ranges, severity, actions, or evidence. The client validates its allowlisted shape before display or storage and renders all text as text.

Each signal has severity (`critical`, `warning`, `info`), numeric engine confidence in `[0,1]`, capture time, exact frame range, and arrays of affected clip and overlay IDs. Referenced IDs must exist in the selected variant and overlap the stated range. Duration and gap observations are checked against Studio metadata; a gap must have no clip of the relevant track kind in its range. `critical` is currently allowed only for a visual gap spanning the whole project. Heuristic preferences and uncertainty cannot use it. The UI should display evidence class, source, confidence, time range converted with the packet timebase, affected IDs, and Studio revision beside critique text. It should preserve the rule ID/version and threshold for auditability.

## Claim and trust rules

The packet contains no object keys, signed URLs, account data, raw targeting, or artist private media. A caller must load the creative's saved project and derive source ID lists from that same reusable creative; the backend must repeat ownership, source, revision, and range checks at its trust boundary. A future engine must compute signals from the selected saved revision and identify its rule version. A frontend must not let model text masquerade as a measured fact or silently turn a heuristic into a defect.

Neither Studio metadata nor these signals measure attention, clicks, conversions, ad approval, safe-area appearance, readability on a device, audio perception, or rendered pixels. Do not claim a creative **will** improve performance or has a visual/audio defect that no analyzer observed. Phrase possible issues as checks or test ideas. The validator rejects unsupported evidence references, extra action/outcome fields, HTML/URLs, and common deterministic performance promises. Natural-language validation is not a proof of factuality: a model integration must instruct the model to stay within cited evidence, and artist-facing review must keep the original evidence visible. Campaign edits and publishing remain the artist's explicit actions in Promotion Center.
